資安防護檔案的目錄結構、用途與啟用方式，方便日後開新專案時隨時查閱。

零、【快速複製】每次開啟 AI 新對話的「黃金開頭指令」
-------------------------------------------------------------------------------
雖然 `.agents/rules/security.md` 已設定在背景自動載入規範，但每次開啟新對話時，
建議直接複製貼上以下這段話（雙重保險，並強制 AI 先回覆確認以加深權重）：

請先熟讀 @.agents/AI_SECURITY_GUIDELINES.md 並務必嚴格遵守其中規範。在我們開始寫程式前，請先簡短回覆確認你已理解這份資安準則。 



💡 額外小技巧：當對話已經進行很久，要準備請 AI 幫你上傳 GitHub 前，可再貼這句：

  │ 請依照 @.agents/AI_SECURITY_GUIDELINES.md 第 5 點進行 Git 提交前安全檢查，│

一、【最重要】GitHub 雲端防線設定步驟 (Secret Scanning & Push Protection)
-------------------------------------------------------------------------------
作用：當你在本地端不小心把含有 API Key（如 OpenAI、Google、AWS、Line、Stripe 等）
      的程式碼 commit 並執行 `git push` 時，GitHub 伺服器會在雲端直接認出金鑰格式
      並「拒絕這次 Push」，防止金鑰外洩到 GitHub 歷史紀錄中。

【方法 A：在個人帳號開啟「全域預設」（推薦！設定一次，以後新開的 Repo 自動生效）】
  1. 登入 GitHub 網站，點擊右上角你的「個人頭像」 -> 選擇「Settings」(設定)。
  2. 在左側選單找到「Code, planning, and automation」區塊，點擊「Code security」。
     (或在新版介面左側直接找「Code security and analysis」)
  3. 往下捲動找到「Secret Protection」或「Secret scanning」區塊：
     - 勾選 / 開啟 (Enable) 「Secret scanning」(機密掃描)
     - 勾選 / 開啟 (Enable) 「Push protection」(推送保護)
     - 勾選「Automatically enable for new repositories」(自動套用到未來新增的儲存庫)

【方法 B：針對單一現有專案 (Repository) 手動開啟】
  1. 進入該 GitHub 專案頁面，點擊上方的「Settings」分頁。
  2. 在左側選單點擊「Code security」(或「Code security and analysis」)。
  3. 找到「Secret scanning」與「Push protection」，點擊右側的「Enable」按鈕開啟。

二、本專案模板的極簡目錄結構與檔案用途（開新專案時直接複製整個資料夾即可）
-------------------------------------------------------------------------------

📁 專案根目錄 (保持極簡，僅留 2 個系統必要的過濾檔)：
  ├── .gitignore       -> Git 版本控制忽略清單，防止 .env、私鑰、資料庫被推上 GitHub。
  ├── .geminiignore    -> AI 底層忽略清單，從系統層阻擋 AI 索引或搜尋 .env 與私鑰。
  └── .agents/         -> 收納所有 AI 規則、說明書與備用範本的子目錄（如下）：

📁 .agents/ 子目錄內的檔案：
  1. rules/security.md
     - 用途：系統自動偵測的專案規則入口檔（設定為 always_on 自動載入）。
     - 用法：放在 `.agents/rules/` 內，AI 啟動時就會自動載入 `AI_SECURITY_GUIDELINES.md`，
             讓根目錄連 `AGENTS.md` 都不需要放，保持最乾淨狀態！

  2. AI_SECURITY_GUIDELINES.md
     - 用途：寫給 AI 看的最高資安守則本文（禁止硬編碼密碼、禁止讀取 .env、個資去識別化等）。

  3. readme.txt (本檔案)
     - 用途：您的個人操作手冊與指令複製區。

  4. .env.example
     - 用途：安全的環境變數範本備用檔（只有變數名稱與假字串，不含真實密碼）。
     - 用法：當專案需要環境變數時，將它複製到「專案根目錄」並改名為 `.env` 填入真密碼；
             若想讓 AI 知道有哪些變數名稱，也可放一份 `.env.example` 在根目錄給 AI 讀。

  5. .pre-commit-config.yaml 與 .gitleaks.toml
     - 用途：本地端 `git commit` 前的自動機密掃描器設定檔（選用進階防線）。
     - 用法：若該專案想啟用本地 pre-commit 掃描，請將這兩個檔案複製到「專案根目錄」，
             並依下方「第三節」的指令啟用。

  6. .aiignore
     - 用途：其他非 Gemini 系 AI 工具專用的忽略清單備用檔，有需要時再複製到根目錄。

三、如何在新專案啟用本地端 Pre-commit 自動攔截工具？（選用進階防線）
-------------------------------------------------------------------------------
如果你希望在執行 `git commit` 時自動啟動 Gitleaks 掃描程式碼中的 API Key：

  步驟 1：將 `.agents/.pre-commit-config.yaml` 與 `.agents/.gitleaks.toml`
          複製一份到「專案根目錄」。

  步驟 2：安裝 pre-commit 工具（整台電腦只需執行一次，需有 Python 環境）
          pip install pre-commit

  步驟 3：在你的 Git 專案根目錄下註冊 Git Hook（每個新專案執行一次）
          pre-commit install

  完成後，每次執行 `git commit`，系統就會自動檢查是否有私鑰、大檔案或 API Key！

四、萬一真的不小心把 API Key 外流出去，該怎麼辦？
-------------------------------------------------------------------------------
切記：「刪除檔案再重新 Commit」是沒用的！因為舊的 Commit 歷史紀錄裡還是看得到。
請務必採取以下步驟：
  1. 【第一步最重要】立刻去該服務的後台（如 OpenAI、Google Cloud、AWS）將該把
     API Key 「撤銷 (Revoke / Delete)」並重新產生一把新的。只要舊 Key 廢除，外流就失效了。
  2. 將新產生的 Key 放入本地 `.env` 中，確認 `.env` 有在 `.gitignore` 內。
  3. 若需要清除 Git 歷史紀錄中的敏感資訊，可使用 `git filter-repo` 或 BFG Repo-Cleaner。
